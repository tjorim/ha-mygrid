# Architecture and contracts

The independently packaged `mygrid-modbus` library accepts a backend-neutral `modbus_connection.ModbusUnit`. It owns battery register decoding, immutable snapshots and command sequences. It has no Home Assistant imports and never constructs, connects, closes or disconnects a transport. The standalone caller chooses a `modbus-connection` backend and owns its connection; optional `tmodbus` and `pymodbus` extras support both.

Home Assistant's `modbus` integration owns the physical connection. MyGrid declares that integration as a dependency and obtains a unit through `async_get_unit(hass, entry, params, 1)`. The manager registers entry-unload cleanup and shares the link by canonical endpoint. Setup errors release the entry's hold; unloading the last consumer closes the socket. Configuration probes use `async_get_temporary_unit` so a probe borrows an existing connection and releases only its temporary hold.

The coordinator holds the shared snapshot and serializes reads and command publication. Entities subscribe through CoordinatorEntity and make no independent polling requests. All 18 registers are read together. A battery-client lock serializes its complete operations; the shared transport serializes individual requests across consumers. The library bounds each operation to 12 seconds after its lock is acquired, including transport queue time. The integration requests a 3-second per-request timeout through `unit.require_timeout(3)`; the owner resolves this with other timeout requirements. Failure messages omit hostnames and raw network exceptions.

Only `number.set_value` and `button.press` can initiate writes. No custom service, raw-register API, timer, shutdown hook or restore-state component writes to the device. A write failure may represent an applied command with a lost acknowledgment; commands are never retried automatically. Both supported backends disable retransmission. Successful setpoint readback confirms acceptance, not actual power delivery. A restart makes cached telemetry unavailable but does not tear down the shared unit. The backend handles a real reboot's lost link on subsequent requests.

Reconfiguration unloads the old entry before probing, preserving entity IDs and history. Releasing the old hold closes the physical connection only when there are no other consumers. Host aliases cannot be reliably deduplicated by this protocol; configure all consumers with one canonical address. The map exposes no serial number, so replacing hardware should create a new entry.

Config-entry schema remains version 1; no migration is required for this transport change. The runtime manifest pins `mygrid-modbus==0.1.0`; `modbus-connection>=4.12.4,<5` is the library's base dependency. Home Assistant supplies `modbus-connection[tmodbus]==4.12.4` and `tmodbus==0.6.2`. Tests pin these Core versions; no backend is pinned by the MyGrid runtime requirement itself.

The library has its own `src/` layout, `py.typed`, wheel/sdist build, tests and release metadata in the sibling `mygrid-modbus` Git repository. The integration contains no transport implementation or register decoder. Local uv sources install the sibling package; Home Assistant resolves the exact manifest requirement from PyPI. Publishing the library remains required before normal installation or core submission.

Protocol and backend tests live in the library repository. The integration's independent raw-frame TCP fixture verifies actual Home Assistant connection sharing: a probe, runtime consumer and peer use one socket; restart and failed setup leave the peer connected; the socket is released after the final hold. No tests import source files from the sibling repository. Physical battery validation is tracked separately.
